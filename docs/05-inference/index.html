05 · Inference

From Slide-Level Output Back to a Patient

Every checkpoint from training was optimized slide-by-slide. Inference has to do the reverse: run the model over a patient's slides, then merge those predictions back into one answer for that patient.

Step 1 · Run inference over held-out slides

The dataset shape is identical to training — one row per (patient, slide) — but now it's a pure forward pass, with patient_id carried through so predictions can be regrouped afterwards:

@torch.no_grad()
def run_inference(model, loader, task: str) -> pd.DataFrame:
    """One row per slide: patient_id, ground truth, and the model's raw output."""
    model.eval()
    rows = []
    for batch in loader:
        wsi = [w.to(DEVICE) for w in batch["wsi"]]
        out = model({"wsi": wsi, "mri": batch["mri"].to(DEVICE), "clinical": batch["clinical"].to(DEVICE)})
        for i, patient_id in enumerate(batch["patient_id"]):
            row = {"patient_id": patient_id, "y_time": batch["y_time"][i].item(), "y_event": batch["y_event"][i].item()}
            if task == "classification":
                row["slide_prob"] = torch.sigmoid(out[i]).item()
            else:
                hazards = torch.sigmoid(out[i])
                survival = torch.cumprod(1 - hazards, dim=0)
                row["slide_risk"] = -survival.sum().item()
            rows.append(row)
    return pd.DataFrame(rows)

Step 2 · Aggregate slide-level predictions to patient level

The aggregation rule differs by task, and deliberately works on probabilities and risk scores, never raw logits — averaging a hazard logit isn't meaningful the way averaging a probability or a risk score is:

Classification

Mean predicted probability across a patient's slides, plus a majority vote for the hard label.

Survival

Mean predicted risk score across a patient's slides.

def aggregate_classification(slide_preds: pd.DataFrame) -> pd.DataFrame:
    return slide_preds.groupby("patient_id").agg(
        y_event=("y_event", "first"),
        mean_prob=("slide_prob", "mean"),
        majority_vote=("slide_prob", lambda p: float((p > 0.5).mean() > 0.5)),
    ).reset_index()

def aggregate_survival(slide_preds: pd.DataFrame) -> pd.DataFrame:
    return slide_preds.groupby("patient_id").agg(
        y_time=("y_time", "first"), y_event=("y_event", "first"),
        mean_risk=("slide_risk", "mean"),
    ).reset_index()

Step 3 · Metrics

With one row per patient, classification gets three metrics — AUROC off the continuous mean_prob, plus balanced accuracy and F1 off the discrete majority_vote label — and survival gets the concordance index:

def evaluate_classification(patient_preds):
    y_true = patient_preds["y_event"]
    return {
        "auroc": roc_auc_score(y_true, patient_preds["mean_prob"]),
        "balanced_accuracy": balanced_accuracy_score(y_true, patient_preds["majority_vote"]),
        "f1": f1_score(y_true, patient_preds["majority_vote"]),
    }

def evaluate_survival(patient_preds):
    return concordance_index(patient_preds["y_time"], patient_preds["mean_risk"], patient_preds["y_event"])

Step 4 · Out-of-fold evaluation

Every fold's checkpoint is scored only on the patients it never trained on — its own validation fold — before all folds' patients are combined into one overall metric per (fusion, task) pair. This is what makes the final numbers in Evaluation & Visualization trustworthy rather than optimistic.

This out-of-fold, patient-level table is also the input to the risk-group stratification in Evaluation & Visualization — computed downstream of these aggregated predictions, never on raw slide-level output.
